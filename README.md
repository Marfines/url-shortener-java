# Сервис сокращения ссылок

[![Java CI](https://github.com/Marfines/url-shortener-java/actions/workflows/ci.yml/badge.svg)](https://github.com/Marfines/url-shortener-java/actions/workflows/ci.yml)

Консольное приложение на Java 17 для создания коротких ссылок с лимитом переходов, системным временем жизни и управлением по UUID владельца. Данные сохраняются между запусками. Сторонних библиотек для работы приложения нет; Maven загружает JUnit и инструменты сборки только при разработке.

Ниже описаны подготовка окружения, запуск приложения, команды и сценарии проверки с ожидаемыми результатами. Для проверки достаточно клонировать репозиторий и выполнить приведённые инструкции; предварительное знакомство с проектом не требуется.

## Возможности

- Уникальные коды Base62 из `SecureRandom`, с проверкой коллизий. Разные пользователи получают разные ссылки на один URL; повторное сокращение также создаёт новый код.
- UUID создаётся при первом успешном сокращении. Один пользователь может иметь несколько ссылок; профили можно переключать.
- Точный счётчик переходов, блокировка после лимита, изменение лимита и адреса назначения владельцем.
- Системный TTL, фоновая очистка, проверка срока при обращении и при запуске.
- Уведомления об исчерпании лимита и истечении TTL. События для неактивного профиля сохраняются до его возвращения.
- Открытие исходного адреса через `Desktop.getDesktop().browse(URI)`.
- Атомарное сохранение данных и блокировка хранилища от второго процесса.

**Приложение работает через консоль.** Адрес вида `https://short.local/Ab12Cd34` — идентификатор внутри приложения. Введите его в консоль программы для перехода. HTTP-сервер и публичный домен для редиректов не разворачиваются.

## Требования и запуск

Нужны **JDK 17 или новее** и **Maven 3.9+**. При первой сборке необходим интернет для загрузки зависимостей из Maven Central. Для открытия браузера нужна обычная графическая сессия ОС и браузер по умолчанию.

```sh
git clone https://github.com/Marfines/url-shortener-java.git
cd url-shortener-java
mvn verify
java -jar target/url-shortener.jar
```

На Windows можно использовать PowerShell-скрипт:

```powershell
.\build.ps1 verify
java -jar target/url-shortener.jar
```

Скрипт использует Maven из `PATH` или встроенный Maven IntelliJ IDEA в `Program Files/JetBrains`. Локальные зависимости он размещает в `.cache/m2` проекта. Если PowerShell блокирует запуск скриптов, воспользуйтесь командами Maven или окном Maven в IntelliJ IDEA — менять политику безопасности не требуется.

В IntelliJ IDEA откройте `pom.xml` как Maven-проект, выберите JDK 17, выполните цель `verify`, затем запустите `ru.marfines.shortener.Main`. Рабочая директория — корень проекта.

Свой файл конфигурации передаётся единственным аргументом:

```sh
java -jar target/url-shortener.jar config/application.properties
```

## Пример работы

```text
> shorten https://www.baeldung.com/java-9-http-client 2
Создана: https://short.local/Ab12Cd34
Ваш UUID: 123e4567-e89b-42d3-a456-426614174000 — сохраните его для возврата к профилю.

> open https://short.local/Ab12Cd34
Открываю: https://www.baeldung.com/java-9-http-client

> Ab12Cd34
Открываю: https://www.baeldung.com/java-9-http-client
Уведомление [Ab12Cd34]: лимит переходов исчерпан; следующие переходы заблокированы.

> open Ab12Cd34
Ошибка: Лимит переходов исчерпан. Ссылка недоступна.

> limit Ab12Cd34 5
> url Ab12Cd34 https://example.org/new
> list
> delete Ab12Cd34
> exit
```

Код и UUID в примере условные: используйте значения, выданные вашим приложением. URL вводится без кавычек; пробелы в адресе необходимо кодировать как `%20`.

## Команды

| Команда | Назначение |
| --- | --- |
| `shorten <URL> [лимит]` | Создать короткую ссылку; без лимита используется значение конфигурации |
| `open <ссылка или код>` | Получить переход и открыть исходный адрес в браузере |
| `<короткая ссылка>` или `<код>` | То же, что `open` |
| `list` | Показать только свои ссылки, счётчики и срок действия |
| `info <ссылка или код>` | Подробности своей ссылки |
| `limit <ссылка или код> <число>` | Изменить общий лимит переходов |
| `url <ссылка или код> <URL>` | Изменить адрес назначения |
| `delete <ссылка или код>` | Удалить свою ссылку |
| `user` | Показать текущий UUID |
| `user new` | Выйти из текущего профиля; новый UUID появится при следующем `shorten` |
| `user use <UUID>` | Выбрать существующий профиль |
| `notifications` | Показать ещё не доставленные уведомления |
| `help` | Подсказки и примеры |
| `exit` / `quit` | Завершить программу; EOF также завершает сеанс |

Новый профиль не удаляет старые данные. Для проверки нескольких пользователей создайте ссылку, сохраните UUID, выполните `user new` и сократите тот же URL. Коды будут разными. Для возврата используйте `user use <сохранённый UUID>`.

UUID служит ключом доступа без пароля: знающий UUID может выбрать соответствующий профиль. Отдельной проверки личности при переключении профиля нет. При проверке прав доступа используйте разные UUID и переключайте их командой `user use`. Доступ к файлу хранилища предполагается доверенным.

## Конфигурация

Все ключевые параметры находятся в [config/application.properties](config/application.properties).

| Параметр | По умолчанию | Правило |
| --- | --- | --- |
| `link.ttl` | `PT24H` | ISO-8601; положительный срок, максимум 3650 дней |
| `link.default-limit` | `10` | Лимит, если пользователь его не указал |
| `link.max-limit` | `1000000` | Верхняя граница нового или изменяемого лимита |
| `link.code-length` | `8` | От 6 до 32 символов Base62 |
| `link.base-url` | `https://short.local/` | Префикс короткой ссылки; заканчивается на `/` |
| `cleanup.interval` | `PT5S` | Интервал фоновой очистки: от `PT0.1S` до `PT1H` |
| `storage.file` | `../data/state.xml` | Путь относительно файла конфигурации |

Параметры читаются при запуске. TTL задаётся администратором в конфигурации, команды для его изменения пользователем нет. Например, `PT1H` — час, `PT24H` — сутки, `PT10S` — десять секунд для демонстрации.

Изменение TTL действует только на новые ссылки. У уже созданной записи хранится абсолютный момент истечения. Изменение адреса или лимита не продлевает TTL и не обнуляет счётчик. При изменении лимита он не может стать меньше числа уже выполненных переходов. Увеличение лимита разблокирует ссылку, если её время жизни ещё не истекло.

В момент `now >= expiresAt` переход уже запрещён. В работающем приложении фоновая задача удаляет просроченные записи примерно раз в `cleanup.interval` (с учётом планирования ОС и времени записи на диск). Любая операция со ссылкой тоже проверяет истечение. Если приложение было выключено, очистка выполняется при следующем запуске. Даты выводятся в UTC с суффиксом `Z`.

## Хранилище и обработка ошибок

`data/state.xml` содержит пользователей, текущий профиль, ссылки, счётчики и недоставленные уведомления. Запись выполняется во временный файл в том же каталоге, сбрасывается на диск и атомарно заменяет предыдущий снимок. Если сохранение не удалось, сервис не применяет изменение в памяти. Нужна файловая система с поддержкой атомарного перемещения; небезопасного запасного способа записи нет.

Параллельные обращения внутри процесса сериализованы. Отдельный файл `.lock` не позволяет двум процессам одновременно открыть одно хранилище. После нормального завершения или завершения процесса ОС освобождает блокировку; наличие файла `.lock` само по себе не означает занятость. Повреждённое хранилище вызывает ошибку запуска и не перезаписывается пустыми данными.

После удаления ссылки исходный URL удаляется. Остаётся минимальная отметка «код + причина удаления», чтобы объяснить недоступность и никогда не использовать код повторно. Такие отметки и зарегистрированные UUID не очищаются; для большого промышленного сервиса потребуются БД и отдельная политика хранения.

Переход учитывается **при успешной выдаче исходного URL** и сохраняется до вызова браузера. Если браузер недоступен, программа показывает исходный URL для ручного открытия и сообщает, что переход уже учтён. Посещение страницы и её доступность в интернете сервис проверить не может. Такой порядок не позволяет потерять счётчик при сбое открытия браузера.

Уведомления активному владельцу выводятся автоматически после команды или из фоновой задачи. Для других профилей они остаются в хранилище. После вывода уведомление считается доставленным. Достижение лимита создаёт уведомление один раз; повторная разблокировка и исчерпание нового лимита создают новое событие.

В Git не включаются `data/`, `target/`, `.cache/` и настройки IDE. Ссылки и UUID пользователей не публикуются.

## Архитектура

| Пакет / модуль | Ответственность |
| --- | --- |
| `Main` | Сборка зависимостей, запуск CLI и жизненный цикл фоновой задачи |
| `config/AppConfig` | Чтение и проверка системной политики |
| `core/Model` | Неизменяемые записи ссылки и уведомления, причины недоступности |
| `core/State` | Копия состояния для атомарной операции |
| `core/ShortenerService` | Уникальность, UUID, права владельца, счётчики, TTL, уведомления |
| `core/StateStore`, `core/CodeGenerator` | Контракты хранилища и генератора |
| `infra/FileStateStore` | Версионированный XML, атомарное сохранение и файловая блокировка |
| `infra/RandomCodeGenerator` | Генерация случайных кодов Base62 |
| `infra/CleanupWorker` | Периодическая очистка без ввода команд |
| `infra/DesktopBrowser` | Открытие браузера средствами Java Desktop |
| `ui/ConsoleApp`, `ui/Browser` | Разбор команд, сообщения и контракт открытия браузера |

Сервис получает `Clock`, `StateStore` и `CodeGenerator` через конструктор. Поэтому время, диск и коллизии в тестах контролируются, а консоль проверяется с подставным браузером без открытия окон. Поиск ссылки работает по коду; одинаковые исходные URL не объединяются. Проверка коллизий учитывает и активные, и ранее удалённые коды.

## Тестирование

```sh
mvn test                 # unit- и интеграционные тесты
mvn verify               # тесты, сборка JAR, javac lint и проверка форматирования
mvn spotless:apply       # применить Google Java Format
```

Эквиваленты для Windows: `.\build.ps1 test`, `.\build.ps1 verify`, `.\build.ps1 format`.

Ожидаемый результат `mvn test`: `Tests run: 52, Failures: 0, Errors: 0, Skipped: 0` и `BUILD SUCCESS`. Команда `mvn verify` дополнительно должна завершить сборку JAR и проверку форматирования без ошибок. Команды сборки выполняются в терминале ОС из корня проекта, а команды `shorten`, `open` и остальные — внутри запущенного приложения.

Набор содержит 52 проверки с учётом параметризованных случаев:

- `ShortenerServiceTest`: UUID, несколько владельцев, изоляция, права, коллизии, лимиты, TTL ровно на границе, уведомления, отказ диска, 100 одновременных запросов и фоновая очистка.
- `PersistenceIntegrationTest`: перезапуск, сохранение счётчиков и уведомлений, очистка на старте, блокировка второго экземпляра и повреждённые данные.
- `ConsoleIntegrationTest`: полный сценарий команд, прямой ввод короткой ссылки, неверный ввод, EOF и недоступный браузер.
- `AppConfigTest`: загрузка настроек, относительные пути, недопустимые значения и неверный формат времени.

Тесты TTL на час и сутки используют управляемые часы и не ждут реального истечения срока. Проверка планировщика ждёт сигнал выполнения с ограничением в пять секунд. Автоматические тесты не проверяют работу установленного браузера или доступность внешних сайтов.

Отчёты JUnit: `target/surefire-reports/`. GitHub Actions запускает `mvn verify` на Linux и Windows, проверяет форматирование Spotless и сохраняет готовый JAR как артефакт. Компиляция с `-Xlint:all -Werror` не допускает предупреждений.

### Подготовка к ручной проверке

После сборки создайте каталог `data` в корне проекта и сохраните в нём файл `qa.properties`:

```properties
link.ttl=PT24H
link.default-limit=10
link.max-limit=1000000
link.code-length=8
link.base-url=https://short.local/
cleanup.interval=PT1S
storage.file=qa-state.xml
```

Запустите приложение с этой конфигурацией:

```sh
java -jar target/url-shortener.jar data/qa.properties
```

Данные проверки будут храниться в `data/qa-state.xml`, отдельно от стандартного хранилища. Для нового независимого прогона завершите приложение и задайте в `storage.file` другое, ещё не использованное имя файла. Для проверки сохранения данных, наоборот, оставьте имя прежним.

В сценариях ниже `<код_A>`, `<код_B>`, `<UUID_A>` и `<UUID_B>` обозначают значения из вывода программы. Подставляйте их без угловых скобок. Выполняйте сценарии по порядку в одном хранилище, кроме отдельной проверки TTL.

### Основные сценарии

| № | Действия | Ожидаемый результат |
| --- | --- | --- |
| 1 | Выполните `shorten https://example.org 2`. Сохраните код ссылки как `<код_A>`, UUID как `<UUID_A>`. Выполните `list`. | Созданы короткая ссылка и UUID. В списке есть ссылка с адресом `https://example.org`, счётчиком `0/2` и временем истечения примерно через сутки. |
| 2 | Выполните `open <код_A>` три раза. Затем выполните `info <код_A>`. | Первые два перехода открывают исходный адрес. После второго появляется уведомление об исчерпании лимита. Третий переход блокируется; счётчик остаётся `2/2`. |
| 3 | Выполните `limit <код_A> 5`, затем введите полную короткую ссылку без команды `open`. | Переход снова разрешён; счётчик становится `3/5`. UUID владельца и время истечения не меняются. |
| 4 | Выполните `url <код_A> https://example.org/updated`, затем `info <код_A>`. | Адрес назначения изменён. Счётчик остаётся `3/5`, время истечения прежнее. |
| 5 | Выполните `user new`, затем `shorten https://example.org 2`. Сохраните `<код_B>` и `<UUID_B>`, выполните `list`. | Новый UUID и код отличаются от первого профиля и ссылки, хотя исходный URL одинаковый. В списке профиля B видна только его ссылка. |
| 6 | В профиле B выполните `info <код_A>`, `limit <код_A> 8`, `url <код_A> https://example.net` и `delete <код_A>`. | Каждая операция отклоняется с сообщением о правах владельца. Ссылка A не изменяется и не удаляется. |
| 7 | Оставаясь в профиле B, выполните `open <код_A>` дважды, затем `user use <UUID_A>`. | Переход по чужой ссылке разрешён и направлен на `https://example.org/updated`; счётчик A достигает `5/5`. Уведомление об исчерпании лимита A получает профиль A после переключения. HTTP-статус целевой страницы не влияет на учёт перехода. |
| 8 | В профиле A выполните `shorten ftp://example.org 2`, `shorten https://example.org 0`, `limit <код_A> 4` и `user use not-a-uuid`. | Все команды отклоняются с понятной ошибкой; приложение продолжает работать. Лимит A остаётся `5`, счётчик — `5`, новые ссылки не появляются. |
| 9 | Выполните `exit`, снова запустите приложение с `data/qa.properties`, затем выполните `user`, `list` и `info <код_A>`. | Восстановлены UUID A, изменённый адрес и счётчик `5/5`. После `user use <UUID_B>` доступна сохранённая ссылка B. |
| 10 | Выполните `user use <UUID_A>`, затем `delete <код_A>`, `list` и `open <код_A>`. | Ссылка A исчезает из списка. Переход отклоняется с сообщением «Ссылка удалена владельцем». Ссылка B сохраняется. |

Если графическая сессия или браузер недоступны, вместо открытия ожидается сообщение о невозможности запуска браузера и исходный URL для ручного перехода. Счётчик при этом увеличивается согласно описанной выше модели учёта. Чтобы проверить именно открытие браузера, повторите сценарии в графической сессии ОС.

### Проверка времени жизни и фоновой очистки

1. Завершите приложение. Скопируйте `data/qa.properties` в `data/ttl.properties`.
2. В копии задайте `link.ttl=PT10S` и `storage.file=ttl-state.xml`. Остальные параметры оставьте прежними. Для повторного независимого прогона используйте новое имя хранилища.
3. Запустите `java -jar target/url-shortener.jar data/ttl.properties` и создайте ссылку командой `shorten https://example.org 5`. Сохраните выданные код и UUID.
4. Не вводите команды до истечения срока и очередного цикла очистки — обычно около 11 секунд после создания. Ожидается автоматическое уведомление об истечении времени жизни.
5. Выполните `list`: созданной ссылки в списке быть не должно. Команда `open <сохранённый код>` должна сообщить, что время жизни истекло и ссылка автоматически удалена.
6. Создайте ещё одну ссылку и сразу выполните `exit`. Подождите более 10 секунд и снова запустите приложение с `data/ttl.properties`. Ожидаются очистка просроченной ссылки при запуске, уведомление владельцу и отсутствие ссылки в `list`.

### Фиксация результатов

Проверка считается успешной, если автоматические тесты завершились без ошибок, а фактическое поведение ручных сценариев совпало с ожидаемым. При обнаружении отклонения укажите версию Java, ОС, коммит проекта, использованную конфигурацию, номер сценария, последовательность команд, ожидаемый и фактический результат. Приложите текст ошибки или соответствующий отчёт из `target/surefire-reports/`.
